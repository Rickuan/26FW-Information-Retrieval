# T4 Query parser（T4a 核心、T4b 加分）

> 草稿：依賴 T1（lexicon 改為 (df, offset, length)、df()、from_config）。T1 實作後依其實作紀錄更新

## 1. 目標
把 query 字串解析成 AST，並列出整個 query 的評分 term 與 query tf，供 T5 過濾、T6 評分。只有一個遞迴下降 parser，接口是 `parse(query, pre)`。T4a／T4b 只代表實作順序與 commit 切分：T4a 先做 `Term`／`And`／`Or`，T4b 再把 NOT、括號、phrase、proximity、wildcard 與拼字建議加進同一個 parser。測試分成核心（`t4.test.py`）與加分（`t4_bonus.test.py`）兩組。

## 2. Index 來源（`HW2/index/`）
`parse` 不讀 index。Preprocessor 一律用 `Preprocessor.from_config(reader.get_metadata()["preprocessor"])` 建立，也就是 casefold、stopword、stem 都是 True，lemma 是 False。測試會用 `term in reader` 確認解析出的 token 都在 dictionary 中。T4b 的 `expand`、`position_match`、`suggest` 會讀 index（經由 `IndexReader`）。

## 3. 接口
AST 已經寫成 `HW2/src/parser.py:19-57` 的真正 dataclass（不是 stub），組員可以直接 import。
```python
# HW2/src/parser.py
Term(tokens: list[str])                             # 沒加引號的運算元，隱含 AND
Phrase(tokens: list[str], positions: list[int])     # "..."，positions 取自 process，保留 stopword 空洞（T4b）
Near(left: Term, right: Term, k: int)               # linux /5 kernel（T4b）
Wildcard(prefix: str)                               # comput*，只做 casefold、不做 stem（T4b）
Not(child: Node); And(children: list[Node]); Or(children: list[Node])
Node = Term | Phrase | Near | Wildcard | Not | And | Or

def parse(query: str, pre: Preprocessor) -> Node | None: ...                          # :60
def expand(node: Node | None, reader: IndexReader, limit: int = 100) -> Node | None: ...  # :78
def query_terms(node: Node) -> Counter[str]: ...                                        # :87
```
**查詢流程固定為** `parse → expand → evaluate（T5）→ query_terms → rank（T6）`：
```python
node = expand(parse("open source AND Linux", pre), reader)   # And([Term(['open', 'sourc']), Term(['linux'])])
cands = evaluate(node, reader)                               # T5；None 代表不過濾
results = rank(query_terms(node), cands, reader)             # Counter({'open': 1, 'sourc': 1, 'linux': 1})
```
`parse` 回傳 `None` 時直接輸出空結果，後面的步驟都不呼叫。

## 4. 改動（T4a 核心）
| 位置 | 改法 |
| --- | --- |
| `HW2/src/parser.py:60-75` `parse` | 遞迴下降 parser，T4a 的範圍見下方步驟 |
| `HW2/src/parser.py:78-84` `expand` | 核心只需處理「樹中沒有 Wildcard」的情況：原樣回傳（`None` 也原樣回傳）。Wildcard 分支先拋出 `NotImplementedError`。因為流程固定會呼叫 `expand`，核心一定要實作這條路徑。 |
| `HW2/src/parser.py:87-95` `query_terms` | 遞迴走過整棵樹，把每個 `Term`／`Phrase` 的 tokens 與 `Near` 兩側的 tokens 全部加進同一個 `Counter`，重複的 token 都要計數。跳過 `Not` 的子樹；遇到 `Wildcard` 拋出 `ValueError`。這些規則很簡單，核心就一次做完。 |

完整語法如下。T4a 只實作標註「T4a」的部分，T4b 在同一個 parser 上擴充：
```
or      := and ("OR" and)*                       # T4a
and     := unary (["AND"] unary)*                # T4a；相鄰的運算元視為隱含 AND（T4b 才會出現）
unary   := "NOT" unary | primary                 # NOT：T4b
primary := WORD+                                 # T4a：連續的 WORD 合成一個 Term
         | "(" or ")" | PHRASE | WILDCARD | WORD "/k" WORD   # T4b
```

`parse` 的步驟（T4a）：
1. 去掉頭尾空白後若是空字串，回傳 `None`，不發出警告。
2. **詞法**：依空白切出 token，並記住字元位置。只有獨立的大寫 `AND`／`OR` 是運算子，所以 `ANDROID`、`and`、`Or` 都不算；其餘都是 `WORD`。運算子在 `process` 之前就切出來，`and`／`or` 是 stopword，順序反過來會被濾掉。
3. **語法分析**：依上面的語法遞迴下降，所以 AND 的優先序高於 OR。`primary` 把連續的 `WORD` 用空白接起來，呼叫一次 `pre.process`，保留**全部** token：`Term([t for _, t in pre.process(text)])`。少了運算元的地方（例如 `linux AND`）產生空的 `Term([])`，交給下一步處理。
4. **空節點規則（在樹上處理）**，由共用的 `_prune(node)` 負責，T4b 也沿用：
   - 空的 `Term`／`Phrase` 從父節點移除，每移除一個就用 `warnings.warn` 警告一次
   - 沒有 child 的 `And`／`Or` 移除；只剩一個 child 時攤平成那個 child；同類型的巢狀節點合併（`And([And([a, b]), c])` → `And([a, b, c])`）
   - `Not` 的 child 是空的就移除這個 `Not`
   - 整棵樹都是空的就回傳 `None`

**與總規劃（`HW2/plans/00-overview.md`）的差異**
- `Preprocessor.process`（`tokenizer.py:94-106`）的位置正確。
- 空運算元的處理改成「在樹上移除」，不再刪除相鄰的運算子。（已回寫）

### 6.1 語法擴充（優先序 NOT > AND > OR）
- **詞法擴充**：改用 `re.finditer(r'"[^"]*"?|[()]|[^\s()"]+', query)` 切出 token，並記住字元位置。新增的 token 類型：
  - `PHRASE`：引號內的文字
  - `(`、`)`
  - 運算子 `NOT`：獨立的大寫 `NOT`
  - `NEAR`：獨立的 `/\d+`
  - `WILDCARD`：結尾是 `*` 的詞
- **語法**：完整語法見第 4 節。`and` 中相鄰的運算元視為隱含 AND，例如 `linux NOT windows` 等於 `linux AND NOT windows`。
- **錯誤**：以下情況拋出 `ValueError`，訊息包含字元位置（從 0 起算）：
  - 引號沒有配對
  - `(` 沒有配對
  - 多出來的 `)`
  - `*`（prefix 是空的）
  - `/0`
  - Near 的一側經過 `process` 後超過一個 token（例如 `e-mail /3 spam`）
- **缺少運算元**時沿用 T4a 規則：產生空節點並發出警告，再交給 `_prune` 處理。例如 `linux AND`、`NOT`、`()`。

### 6.2 Phrase、6.3 Near（`position_match`）
- `"open source"` → `Phrase(['open', 'sourc'], [1, 2])`；`"lord of the rings"` → `Phrase(['lord', 'ring'], [1, 4])`。
- 只有一個 token 的 phrase 會簡化成 `Term`；空的 phrase 依空節點規則移除。
- **Phrase 的比對**：先找出全部 token 都出現的文件。對每篇文件，檢查是否存在 p，使每個 `tokens[i]` 都出現在 `p + positions[i] - positions[0]`；用 set 查詢。
- **Near 的比對**：兩邊的 position list 已排序，用雙指標找是否有 `|p_l - p_r| ≤ k`，不分先後。Near 某一側是空的（stopword）時，退化成另一側的 `Term`，並發出警告。
- 位置以含 stopword 的 token 位置計算，與 index 相同。

### 6.4 Wildcard（`expand`）
- `Comput*` → `Wildcard('comput')`：只做 casefold，不做 stem。所以 `computing*` 對不到 dictionary 中的 `comput`，會展開成空的結果並發出警告。這是已知限制，要寫進文件。
- **展開方式**：用 `reader.prefix_terms(prefix)` 取得候選，依 `(-df, term)` 排序後取前 `limit` 個（預設 100），組成 `Or([Term([t]) ...])`。
  - 超過 `limit` 時發出一次警告，訊息包含總數
  - 只有 1 個時就是 `Term`
  - 0 個時依空節點規則移除
- 不修改傳入的樹，回傳新的樹。

### 6.5 拼字更正（`suggest`）
- **輸入**：dictionary 形式的 token（`process` 之後的結果）。
- **候選與排序**：
  - 用 `vocabulary()` 建立 bigram（前後加 `$`）的 k-gram index，第一次呼叫時建立並依 reader 快取
  - 候選條件是 Jaccard ≥ 0.3，排除 term 本身
  - 依 `(Damerau-OSA 距離, -df, term)` 排序，取前 `limit` 個
- **只提供「Did you mean」建議**，不自動替換。
- **觸發條件**（已決定，由 T7 判斷）：原詞的 df == 0，或最佳建議的 df ≥ 原詞 df × 10。
  - `retreival` 經過 stem 後是 `retreiv`，它本身就在 dictionary 中（df 11，是語料裡的錯字），所以只靠第一條不會觸發。
  - 最佳建議 `retriev` 的 df 是 409 ≥ 110，第二條會觸發。
- **限制**：dictionary 存的是 stem 過的詞，建議的結果也是 stem 形式。例如建議的是 `retriev`，不是 `retrieval`，畫面上要說明。
- **預先量測**（暴力掃描版，k-gram index 會更快）：`suggest('retreival')` 的前三名是 `retreiv`、`retrial`、`retriev`；`suggest('retreiv')` 的第一名是 `retriev`（df 409）。

### 6.6 Soundex（優先度低）
- 標準 American Soundex：保留第一個字母，其餘字母轉成數字；h／w 不隔開相同的數字。
- `suggest_soundex` 只比對純字母的 term，依 `(-df, term)` 排序。
- **stem 的影響**：Soundex 只看第一個字母加上前三個子音碼，而 stem 通常只去掉字尾，所以多數 stem 和原形同碼（`comput`、`computer` 都是 C513）。但短字被 stem 時可能落到不同的碼。dictionary 約 57 萬個 term，Soundex 碼只有約 9 千種，碰撞非常多，所以只能當作輔助建議。
