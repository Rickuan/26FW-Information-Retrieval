# T3 只取 doc／tf 的快速讀取

> 草稿：依賴 T1（lexicon 改為 (df, offset, length)、df()、from_config）。T1 實作後依其實作紀錄更新

## 1. 目標
新增 `get_doc_tf(term)`，只解出 (doc_num, tf)、跳過 positions，讓 T5、T6 取 posting 時不必建立 `Posting` 物件。

## 2. Index 來源（`HW2/index/`）
使用 T1 的 stop+stem index，只讀 `lexicon.tsv`（取 offset、length）與 `postings.bin`。

- **block 格式**：`[df: uint32 BE]` 之後是每筆 posting 的 `[Δdoc][tf][n_pos][Δpos × n_pos]`，全部是 VByte。寫入端在 `writer.py:156-168`，讀取端在 `writer.py:184-203`。
- **測試用的代表 term**：
  - 高 df：`home`（22,611）、`new`（18,412）
  - 中 df：`linux`（997）、`kernel`（279）
  - df = 1：lexicon 的第一個 term `,ltd.is`。df = 1 的 term 共 375,134 個。

## 3. 接口
```python
# HW2/src/writer.py
class IndexReader:
    def get_doc_tf(self, term: str) -> tuple[list[int], list[int]]: ...
        # (doc_nums, tfs)，doc_nums 嚴格遞增；term 不存在回傳 ([], [])
```
```python
reader = IndexReader("HW2/index")
docs, tfs = reader.get_doc_tf("linux")        # len(docs) == reader.df("linux") == 997
for d, tf in zip(docs, tfs): ...
reader.get_doc_tf("不存在的詞")                 # ([], [])
```

## 4. 改動
| 位置 | 改法 |
| --- | --- |
| `HW2/src/writer.py:366` 之後 `__init__` | 新增 `self._mm: mmap.mmap \| None = None` |
| `HW2/src/writer.py` 新增 `_postings_mm()` | 第一次呼叫時用 `mmap.mmap(f.fileno(), 0, access=mmap.ACCESS_READ)` 開啟 `postings.bin` 並快取。之後所有呼叫共用同一個 mmap。 |
| `HW2/src/writer.py:475-481` `get_doc_tf` | 用 `_load_lexicon().get(term)` 取得 `(df, offset, length)`，不存在時回傳 `([], [])`。讀出 block 的 df 標頭後，逐筆解 Δdoc、tf、n_pos，再跳過 n_pos 個 VByte：每個值掃到最高位為 0 的 byte 為止，不做數值運算。VByte 迴圈寫成內聯，不呼叫 `decode_vbyte`，省掉函式呼叫的開銷。 |
| `writer.py` import | 加 `import mmap` |

- **檔案策略選 mmap**：T2 的 build 與 T6 的單次 query 都會對同一個 reader 呼叫很多次。mmap 只開檔一次，之後每次查詢都是記憶體切片，沒有 seek／read 的系統呼叫，也不必把 block 複製成 `bytes`。分頁由 OS 快取，63 MB 的檔案不會整份讀進 RSS。另一個做法是「保留一個開著的 file handle 再 seek + read」，它同樣只開檔一次，但每次查詢仍要做系統呼叫並複製資料，所以不選。
- 用 `ACCESS_READ` 在 Linux、macOS、Windows 都可以用。T3 不新增 `close()`，mmap 隨 reader 一起被回收。
- 既有的 `get_postings`（`writer.py:402-416`）與 `decode_postings_block` 完全不動，留給 phrase／proximity 使用。

**與總規劃（`HW2/plans/00-overview.md`）的差異**
- 總規劃引用 posting 格式在 `writer.py:157-168`，實際寫入迴圈是 `:156-168`，讀取端是 `:184-203`。stub 的位置在 `writer.py:475-481`。
- 檔案策略選定 mmap。（已回寫）
- 總規劃說「實測高 df 詞完整解碼可達 128 ms」，這個數字尚未在 HW2 重測，以本任務的計時結果為準。

## 6. 加分項（核心合併後才開始）
兩項都是新增的 method。快取預設關閉，所以 `get_doc_tf` 的核心行為不變。stub 已在 `writer.py` 建立。

### 6.1 `get_champions`（優先度：低）
- **評分面向**：效率（不精確 top-k）
- **接口**：`IndexReader.get_champions(term: str, r: int = 50) -> tuple[list[int], list[int]]`（`writer.py:502`）
- **改動**：`writer.py`。
  - 第一次呼叫時，載入 `champions.r<r>.tsv` 與 meta，並以 `get_norms` 相同的方式核對來源檔的 size／sha256。
  - `champions.r<r>.bin` 用 mmap 讀取，解碼 `[n][Δdoc][tf]…`。
  - term 不在 champion 檔、但在 lexicon 中時（df ≤ r），直接回傳 `get_doc_tf(term)`。term 不存在時回傳 `([], [])`。
  - 檔案不存在時拋出 `FileNotFoundError`；meta 不一致時拋出 `ValueError`。
- **依賴**：T3 核心、T2 加分 6.2（champion 的格式與建置）

### 6.2 `get_doc_tf` 的 LRU 快取（優先度：低）
- **評分面向**：效率
- **接口**：`IndexReader.set_doc_tf_cache(maxsize: int) -> None`（`writer.py:515`），0 代表關閉（預設），重設時清空快取；`IndexReader.doc_tf_cache_info() -> tuple[int, int]`（`writer.py:519`），回傳 (hits, misses)。
- **改動**：`writer.py`。
  - 用 `collections.OrderedDict` 實作，key 是 term，value 是 `(array('I'), array('I'))`。
  - 命中時回傳 `list(...)` 複本，呼叫端修改回傳的 list 不會污染快取。
  - 快取關閉時不計數，`get_doc_tf` 走核心路徑。
- **依賴**：T3 核心
