# T6 VSM 排序引擎規劃

## 1. 目標
實作 `HW2/src/rank.py` 之 `rank(qtf, candidates, reader, scheme="ltc.ltc", champion_r=None) -> list[tuple[int, float]]`。
以向量空間模型（VSM）計算 query 與候選文件之相似度，回傳所有分數大於 0 並依 `(-score, doc_num)` 嚴格排序的結果清單。

## 2. 上游依賴與接口
- **W `weighting.py`**：`weight(tf, df, N, scheme)`、`formula(scheme)`
- **T1/T3 `writer.py`**：
  - `reader.N`、`reader.df(term)`
  - `reader.get_doc_tf(term) -> (docs, tfs)`
  - `reader.get_norms(scheme) -> array('d')`
  - `reader.get_champions(term, r) -> (docs, tfs)`
- **T4 `parser.py`**：`query_terms(node) -> Counter[str]` 提供詞頻 $tf_{t,q}$。
- **T5 `boolean.py`**：`evaluate(node, reader) -> set[int] | None` 提供候選文件集合。

## 3. 前置技術決策與核心演算法

### 3.1 權重方案解析與邊界防呆
- **Scheme 嚴格解析（方案 A）**：
  - 輸入 `scheme` 格式必須為 `<doc_scheme>.<query_scheme>`（剛好 1 個小數點、總長 7 碼），否則拋出 `ValueError`。
  - 前後各自為 3 碼合法 SMART 標記；分別以 `formula` 驗證其合法性，不合規拋 `ValueError`。
- **提早 Short-circuit 判定**：
  - 若 `candidates is not None and len(candidates) == 0`，直接回傳 `[]`。
  - 若 `qtf` 為空（如純 NOT 查詢無評分詞），依 VSM 定義無查詢向量，直接回傳 `[]`。

### 3.2 Query 向量計算與長度正規化
1. 逐評分詞 $t \in \text{qtf}$：
   - 取得 $df = \text{reader.df}(t)$。若 $df == 0$，該詞不參與評分。
   - 透過 `weight(qtf[t], df, reader.N, query_scheme)` 計算 $w_{t,q}$。
2. 計算 query 向量長度 $|q|$：若 `query_scheme` 之 normalization 為 `'c'`，則 $|q| = \sqrt{\sum w_{t,q}^2}$；若為 `'n'` 則 $|q| = 1.0$。
3. 若全部詞項權重皆為 0 或 $|q| == 0$，直接回傳 `[]`。

### 3.3 Term-at-a-time (TAAT) 分子累加器
1. 初始化累加器 `acc: dict[int, float] = defaultdict(float)`。
2. 逐一走訪有效評分詞 $t$：
   - 取出已快取之 $df$ 與 $w_{t,q}$。
   - 資料來源：若 `champion_r` 有設定則呼叫 `reader.get_champions(t, r=champion_r)`；否則呼叫 `reader.get_doc_tf(t)`。
   - 走訪各篇命中文件 $(d, tf)$：
     - 若 `candidates is not None and d not in candidates` 則略過。
     - 計算 $w_{t,d} = \text{weight}(tf, df, reader.N, doc_scheme)$。
     - 累加內積：`acc[d] += w_td * w_tq`。
3. 若 `len(acc) == 0`，提早 short-circuit 直接回傳 `[]`（避免磁碟讀取 norms 檔之 I/O 開銷）。

### 3.4 相似度計算、破同分與回傳
1. 透過 `reader.get_norms(doc_scheme)` 取得預存之全量文件長度陣列 `norms`。
2. 對所有累加命中之文件 $d$（走訪 `acc`）：
   - 若 $norms[d] <= 0$，略過。
   - $\text{score} = \frac{\text{acc}[d]}{norms[d] \times |q|}$。
   - 僅保留 $\text{score} > 0$ 者。
3. 依 `key=lambda x: (-x[1], x[0])` 排序（以原始 float 分數高者在前；完全同分時，依 `doc_num` 嚴格遞增）。
4. **職責分離**：T6 回傳所有符合之全量排序清單；`--top-k` 截斷與 6 位小數輸出格式化由下游 T7 CLI 負責。

## 4. 測試策略 (`HW2/tests/t6.test.py`)
- **手算小語料 Mock 測試**：
  - 構造 3 篇文件微型索引，精準對照手算 cosine 分數至小數點後 6 位。
- **排序與同分 Tie-breaking 驗證**：
  - 構造相同分數之文件，驗證嚴格依原始分數降冪、同分時依 `doc_num` 遞增排序。
- **候選過濾（T5 整合）驗證**：
  - 對照 `candidates=None`（全域自由召回）與 `candidates={...}`（布林嚴格過濾）之召回文件子集。
- **加分項驗證**：
  - SMART scheme 切換（`ltc.ltc`、`lnc.ltc`、`bnn.bnn`）。
  - `champion_r=50` 不精確 top-k 召回與評分流程。
- **防呆與邊界測試**：
  - 非法 scheme（格式錯誤、無小數點、非法字母）拋 `ValueError`。
  - 純 NOT 查詢（`qtf` 為空）、全不存在詞、無候選命中等邊界，驗證回傳 `[]`。
- **真實 HW2 索引端到端測試**：
  - 執行作業範例查詢（`Microsoft`、`open source AND Linux`），驗證 cosine 模式下輸出非空、分數介於 (0, 1] 且嚴格遞減；`'n'` 方案驗證分數非負。
