# T2 預算文件 norm（含 W：`weight()`）

> 草稿：依賴 T1（lexicon 改為 (df, offset, length)、df()、from_config）。T1 實作後依其實作紀錄更新

## 1. 目標
實作共用權重函式 `weight()`，並一次掃過整個 index，預先算出每篇文件的 |d|，存檔後供 T6 的 cosine 分母直接載入。

## 2. Index 來源（`HW2/index/`）
使用 T1 的 stop+stem index：N = 34,786，doc_num 從 0 到 34785 連續，共 573,233 個 term。唯一的空文件是 doc 24621（`doc_len = 0`）。T2 會新增兩個檔案，其餘檔案不動。

| 檔案 | 用途 | T2 讀／寫 |
| --- | --- | --- |
| `lexicon.tsv`、`postings.bin` | 依 term 逐一取出 (doc, tf) | 讀 |
| `metadata.json` | N | 讀 |
| `postings.txt` | 只給測試的獨立路徑使用 | 測試讀 |
| `doc_norms.bin` | `array('d')`，長度 N，下標 = doc_num（約 278 KB） | **新增** |
| `doc_norms.meta.json` | 記錄公式與來源 index 的指紋 | **新增** |

## 4. 改動
| 位置 | 改法 |
| --- | --- |
| `HW2/src/weighting.py:12-24` `weight` | scheme 不是 `"ltc"` 時拋出 `ValueError`（其他 scheme 屬於加分項）。`if tf <= 0 or df <= 0: return 0.0`，否則 `return (1 + math.log10(tf)) * math.log10(N / df)`。只能用 `math.log10`。 |
| `HW2/src/weighting.py:27-33` `norm_filenames` | `"ltc"` 回傳 `("doc_norms.bin", "doc_norms.meta.json")`。`build_norms` 與 `get_norms` 都經由它取得檔名。 |
| `HW2/src/build_norms.py:12-18` `build_norms` | `norm2 = array('d', bytes(8 * N))`。依 `reader._load_lexicon()` 的順序逐一處理 term：`postings.bin` 只開一次，依 offset／length 讀出 block，用 `decode_postings_block`（`writer.py:173`）解碼，再累加 `norm2[doc] += weight(tf, df, N) ** 2`。最後開根號，寫出 `doc_norms.bin`（`array.tofile`）與 meta。結束時印出建置時間（`time.perf_counter`）與峰值記憶體（`resource.getrusage(...).ru_maxrss`，同 HW1 `indexer.test.py:66`）。另外補上 `argparse` 的 `--index-dir`、`--scheme`。 |
| `doc_norms.meta.json` 欄位 | `log_base: 10`、`formula: "(1+log10 tf)*log10(N/df)"`、`scheme: "ltc"`、`N`、`count`（= N），以及 `lexicon.tsv`、`postings.bin`、`metadata.json` 各自的 `size` 與 `sha256` |
| `HW2/src/writer.py:460-473` `get_norms` | 第一次呼叫時讀 meta 並核對：`log_base`、`formula`、`scheme` 要等於 `weighting` 的常數與要求的 scheme；`N` 要等於 `self.N`；三個來源檔的 size 與 sha256 都要相符；norm 檔大小要等於 `8 × N`。任何一項不符就拋出 `ValueError`，訊息指出是哪一項。檔案不存在時拋出 `FileNotFoundError`，提示先跑 `build_norms.py`。結果依 scheme 快取。 |

- 核對用 sha256 而不是只比大小。實測三個檔案共約 0.08 秒，每個 process 只做一次。
- 公式常數（`LOG_BASE`、`FORMULA`、`DEFAULT_SCHEME`）只在 `weighting.py` 定義，`build_norms.py` 寫入、`get_norms` 核對，兩邊都引用這一份。
- T3 完成後，`build_norms.py` 可以把解碼換成 `get_doc_tf`，結果必須逐 byte 不變。

**與總規劃（`HW2/plans/00-overview.md`）的差異**
- W 改由 T2 負責，放在 `weighting.py`（避免與 T6 同時修改 `rank.py`）。（已回寫）
- `get_norms()` 在載入時核對 meta，不一致時拋出 `ValueError`。（已回寫）
- 總規劃說「那篇空文件」，實際是 doc 24621。
- `get_postings`（`writer.py:402`）的位置仍然正確，但 build 不用它，因為它每次呼叫都要重新開檔，57 萬次太慢。

## 6. 加分項（核心合併後才開始）
所有新參數都有預設值，預設值的行為與核心完全相同。

### 6.1 SMART 權重方案（優先度：高）
- **評分面向**：權重方案
- **字母意義**（SMART 記法 `ddd.qqq`，例如 `lnc.ltc` 代表文件用 lnc、query 用 ltc）：

  | 位置 | 字母 | 意義 |
  | --- | --- | --- |
  | tf | `n` | tf 原值 |
  | tf | `l` | 1 + log10 tf |
  | tf | `b` | 1（tf > 0 時） |
  | idf | `n` | 1（不用 idf） |
  | idf | `t` | log10(N / df) |
  | normalization | `n` | 不正規化，\|d\| 視為 1 |
  | normalization | `c` | cosine：除以 sqrt(Σw²) |

  至少支援 ltc（預設）、lnc、bnn；三個位置各自寫成小函式，所以所有組合都能用。
- **接口**：`weight(tf, df, N, scheme="ltc")`（`weighting.py:12`）、`norm_filenames(scheme)`（`weighting.py:27`）、`get_norms(scheme="ltc")`（`writer.py:460`）、`build_norms(index_dir, scheme="ltc")`（`build_norms.py:12`）。CLI 是 `--scheme X`。
- **改動**：
  - `weighting.py`：依字母分派。`weight` 只看前兩個字母，第三個字母由 norm 負責。
  - `norm_filenames`：非 ltc 時回傳 `doc_norms.<scheme>.bin`、`doc_norms.<scheme>.meta.json`。
  - `build_norms.py`：normalization 是 `c` 時照核心流程掃描，並把 scheme 傳給 `weight`；是 `n` 時不必掃描，直接寫入全部為 1.0 的 array。meta 的 `scheme`、`formula` 依 scheme 填寫。
  - `get_norms`：核對時也比對 meta 的 `scheme`。
  - 預設檔名與 ltc 的行為與核心完全相同。
- **依賴**：T2 核心
- **驗收測試**：見 6.3。

### 6.2 Champion list（優先度：低）
- **評分面向**：效率（不精確 top-k）
- **接口**：`build_champions(index_dir, r=50)`（`build_champions.py:14`）。CLI 是 `uv run python HW2/src/build_champions.py --index-dir HW2/index [--r 50]`。
- **格式與檔名**：
  - `champions.r<r>.bin`：每個 term 一個 block，格式是 `[n: uint32 BE]` 加上 n 組 `[Δdoc: VByte][tf: VByte]`，doc 遞增。沒有 positions。
  - `champions.r<r>.tsv`：`term \t n \t offset \t length`，字典序。
  - `champions.r<r>.meta.json`：記錄 `r`、選取規則 `"(-tf, doc)"`，以及來源 `lexicon.tsv`、`postings.bin` 的 size 與 sha256。
  - 只收 df > r 的 term。df ≤ r 的 term，champion list 就是完整的 postings，由 `get_champions` 直接回傳 `get_doc_tf` 的結果。r = 50 時只需收 15,755 個 term，其餘 557,478 個（97.3%）都不必寫入。
- **改動**：`build_champions.py`。依 `(-tf, doc)` 取前 r 筆，再依 doc 遞增排序後寫出。檔名帶 r，所以不同的 r 可以並存。
- **依賴**：T1 核心、T3 核心（用 `get_doc_tf` 讀取，不需要 positions）。T3 加分的 `get_champions` 讀取這些檔案。
