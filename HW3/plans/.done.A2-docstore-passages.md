## 2. 介面設計

**`rag/passages.py`**（純函式；參數由呼叫端從 config 傳入）

| 函式 / 常數 | 說明 |
|---|---|
| `MIN_SPLIT_WORDS = 30` | 少於此字數的文件整篇一段（見 3. 規則 3、D2） |
| `split_passages(text, passage_words, passage_stride) -> list[tuple[int, int, str]]` | 回傳 `(start_word, end_word, text)`，含頭不含尾，依 start 遞增 |
| `number_passages(docs, passage_words, passage_stride) -> Iterator[tuple[int, int, int, int, str]]` | `docs` 為 `(docid, text)` 的 iterable；產出 `(pid, docid, start, end, text)`，pid 從 0 全域連續 |

- 參數檢查：`passage_words ≥ 1` 且 `1 ≤ passage_stride ≤ passage_words`，否則 `ValueError`（stride > words 會漏字；stride = 0 會無窮迴圈）。

**`rag/docstore.py`**

| 函式 / 類別 | 說明 |
|---|---|
| `build_docstore(warc_path, db_path, limit, *, doc_map_path, passage_words, passage_stride) -> dict` | 資料來源 `hw_bridge.iter_documents(warc_path, limit)`；回傳 `{n_docs, n_passages, n_empty_docs, seconds}` |
| `Doc(docid, trec_id, url, text)`、`Passage(pid, docid, start_word, end_word, text)` | frozen dataclass |
| `DocStore(db_path)` | 唯讀開啟（`file:...?mode=ro` URI）；檔案不存在 → `FileNotFoundError`；支援 `with` 與 `close()` |
| `.get_doc(docid) -> Doc`、`.get_passage(pid) -> Passage` | 不存在 → `KeyError` |
| `.get_passages_by_doc(docid) -> list[Passage]` | `ORDER BY pid`；空文件或 docid 不存在 → `[]` |
| `.count_passages() -> int`、`.iter_passages(start_pid=0) -> Iterator[Passage]` | 給 embedding 階段（A3/A4）依 pid 分批與續跑用 |

- 建置後的檢查一律以明確 `raise ValueError` 實作，不用 `assert` 敘述（`python -O` 會略過）：
  1. `COUNT(docs) == len(doc_map.json)`，且 docid 集合 = doc_map 的 key 集合（字串 key 轉 int）。
  2. passages 的 `MIN(pid) = 0`、`MAX(pid) = COUNT - 1`（或兩者皆無資料）。
- 唯讀連線用 `check_same_thread=False`（LangChain 的 `batch()` 可能跨執行緒；唯讀查詢安全）。

## 3. 切分規則

設 `words = text.split()`（Python 無參數 split：任何 Unicode 空白皆為分隔、連續空白視為一個、頭尾忽略），
`n = len(words)`，`W = passage_words`，`S = passage_stride`。

1. **空文件**（`n == 0`，含只有空白）：回傳 `[]`，不佔 pid；`docs` 表仍寫入該文件（文件數要等於 doc_map）。
2. **`n ≤ W`**：整篇一段 `[(0, n, ...)]`。
3. **`n < MIN_SPLIT_WORDS`**：整篇一段（`W ≥ 30` 時已被規則 2 涵蓋；只有 `W < 30` 時才有作用，見 D2）。
4. **其餘**：起點 `s = 0, S, 2S, …`，每段 `[s, min(s + W, n))`；**某段的結尾等於 `n` 就停止**。
   - **尾端涵蓋**：最後一段固定結束於 `n`，所以最後一個字一定被涵蓋；相鄰兩段重疊 `W − S` 字，沒有空隙。
   - **最後一段的長度**：前一段結尾 `< n`，所以最後一段至少 `W − S + 1` 字（300/250 時 ≥ 51 字），不會出現極短的尾段。
   - 段數 = `1 + ceil((n − W) / S)`；例：`n = 301` → `[0,300)`、`[250,301)`；`n = 551` → 3 段，最後 `[500,551)`。
5. **passage 文字** = `" ".join(words[start:end])`：換行、tab、連續空白都正規化為單一空白（D3）；
   `start_word/end_word` 精確對應 `docs.text.split()` 的位置，可由 docs 重算。
6. **任何長度 ≤ `W − S` 字的連續片段，必定完整落在某一段之內**（片段起於 a 時，取起點 `min(⌊a/S⌋·S, 最後一段的起點)` 的那一段）。
   埋入句子約 13 字 ≤ 50，因此一定完整出現在某段 passage 中；V1/V2 實測確認。
7. **pid 全域連續**：`number_passages` 依 docs 的輸入順序（WARC 順序 = docid 遞增）、每篇內依 start 遞增編號，從 0 起；空文件不佔號。

## 5. 單元測試（`passages.test.py`，依 1.6-7 的匯入與執行方式）

1. 空字串、只有空白 → `[]`；`n = 1`、`n = W` → 一段；`W = 10, n = 25`（< 30）→ 整篇一段（規則 3）
2. `W = 300, S = 250`：`n = 301`、`550`、`551` 的分段與第 3 節的例子相同；段數公式；參數不合法 → `ValueError`
3. 性質：`n ∈ [0, 1200)` × 多組 `(W, S)`（含 `S = W`、`S = 1`）→ 起於 0、止於 n、無空隙、起點為 S 的倍數、
   每段 ≤ W 字、尾段 ≥ `W − S + 1`；任意 ≤ `W − S` 字的片段完整落在某段之內（規則 6）
4. 文字：混合 `\n`、`\t`、連續空白、`\xa0` → 每段 = `" ".join(words[s:e])`
5. `number_passages`：含空文件的多篇輸入 → pid 從 0 連續、空文件不佔號、順序正確

## 6. 驗證計畫（腳本在 `scratch/a2/`，產物也寫在這裡，不寫入正式或 fixtures 路徑）

- **V1 `--limit 200`**：先以 `hw_bridge.build_lexical_index(..., scratch/a2/index200, 200)` 產生 doc_map；**V2 全量**：doc_map 見 D6。
- 兩者都檢查（`scratch/a2/validate.py`）：
  1. 文件數 = doc_map 筆數；docid 集合相同；每個 docid 的 `trec_id`、`url` 與 doc_map 相同
  2. pid 為 0..N−1 連續；依 pid 排序時 `(docid, start_word)` 嚴格遞增
  3. **涵蓋**：每篇 `words = text.split()`，其 passages 第一段起於 0、最後一段止於 `len(words)`、相鄰無空隙，
     且每段 text = `" ".join(words[s:e])`；空文件 0 段、非空文件 ≥ 1 段
  4. **埋入句子**：依 config 的 `[[inject.tokens]]` 由 trec_id 找到 docid（V1 只取 docid < 200 的目標），
     每篇至少有一段 passage 包含空白正規化後的整句
  5. 統計：passage 數、每段字數與字元數分布、資料庫大小、耗時、`get_*` 查詢延遲

## 7. 決定與理由

- **D1 尾段規則**：起點固定為 S 的倍數，最後一段截到 n（不是另外把最後一段對齊結尾、固定 W 字）。理由：起點可預測、易於測試；尾段至少 51 字已足夠；不產生與前一段重疊過多的段落。
- **D2 `MIN_SPLIT_WORDS = 30` 寫成模組常數**，不放進 config：`W ≥ 30` 時規則 3 不會有作用，加進 config 要改 1.3。
- **D3 passage 文字以單一空白 join**：與 start/end 字位置一一對應；換行對 LLM 與 embedding 沒有必要。
- **D4** 讀取端用 `DocStore` 類別（方法名稱沿用 2.4 的 `get_doc` 等），讓查詢期重用同一個連線，路徑由呼叫端以 `paths(...)["docstore"]` 傳入。
- **D5** docstore 階段再讀一次 WARC（與 index 階段各讀一次，多約 3.5 分鐘），不修改 A1 的 `hw_bridge` 介面。
- **D6 V2 全量驗證使用 `HW2/index/doc_map.json`**：注入不改變文件數與 trec_id，省下約 9 分鐘的全量建索引。
- 以上 D1、D3、D5、D6 及待修訂第 1 項均已經使用者確認（2026-11-27）。

**與計畫的落差**：(1) `build_docstore` 每 1,000 篇呼叫一次 `number_passages`（每次從 0 編號），再平移成全域 pid，
結果相同（V2 檢查 2）；(2) 單元測試共 12 個 test，涵蓋第 5 節全部項目；(3) 規模與預估相符，資料庫略大（458 MB）。
