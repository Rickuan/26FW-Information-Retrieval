## 2. 介面設計

**`rag/embed.py`**（只依賴 `langchain_core`、`langchain_ollama`、`numpy`；`langchain_ollama` 延後匯入）

| 名稱 | 說明 |
|---|---|
| `class PrefixedOllamaEmbeddings(Embeddings)` | 一般類別；`__init__(model, query_prefix, doc_prefix, *, num_gpu=None, inner=None)` |
| `.from_config(mode: Literal["build", "query"], cfg=None, *, inner=None)` | 由 `cfg["embed"]` 取 model / 前綴；`build` → `num_gpu=None`（GPU）；`query` → `num_gpu=0`（CPU） |
| `.embed_documents(texts)` / `.embed_query(text)` | 一律加一次 `doc_prefix` / `query_prefix`；輸入已以該前綴開頭 → `ValueError`；整批一次送出 → L2 normalize |
| `l2_normalize(vecs) -> np.ndarray` | float32；非二維、零向量或非有限值 → `ValueError` |

- `inner` 預設為 `OllamaEmbeddings(model, num_gpu, dimensions=None)`，不傳 `truncate`（長輸入見 D2）；測試注入假的 inner。

**`rag/vectorstore.py`**（唯一匯入 `faiss`、`FAISS`、`DistanceStrategy` 的模組；匯入路徑依 2.5 步驟 1）

| 名稱 | 說明 |
|---|---|
| `ckpt_meta_from_config(cfg, *, limit, n_passages) -> dict` | checkpoint 設定（第 3 節） |
| `embed_passages(db_path, ckpt_dir, embeddings, *, batch_size, ckpt_meta) -> dict` | embedding 階段；回傳 `{n_passages, n_batches, n_new_batches, resumed_from, seconds}`；進度每 10 秒寫 stderr |
| `is_embed_done(ckpt_dir, ckpt_meta) -> bool` | 設定相同且涵蓋全部 pid；不修改檔案（給 build.py 判斷跳過） |
| `build_vectorstore(db_path, ckpt_dir, vectorstore_dir, embeddings) -> dict` | 逐檔組裝並存檔；回傳 `{ntotal, n_batches, seconds}` |
| `open_vectorstore(vectorstore_dir, build_meta_path, cfg=None) -> FAISS` | 實際載入邏輯（D4） |
| `load_vectorstore(fixtures: bool) -> FAISS` | 給 B：`open_vectorstore(paths(fixtures)[...])` 的薄包裝 |
| `EmbedMismatchError(RuntimeError)` | build_meta 的 `embed_model / query_prefix / doc_prefix / dim` 與 config 不同 |

- **組裝**：第一個 checkpoint → `FAISS.from_embeddings(..., distance_strategy=MAX_INNER_PRODUCT)` → 檢查 `IndexFlatIP` 與 dim；其餘逐一 `add_embeddings`。
  text / docid 由 `DocStore.iter_passages(0)` 依 pid 對齊並檢查；metadata `{"pid", "docid"}`、`ids=str(pid)`；不傳 `normalize_L2`。
  `ntotal == count_passages()` 後 `save_local` 到 `<dir>.tmp`，再換成正式目錄（存在 ⇔ 完整；既有目錄被取代）。FAISS 第 i 個向量 = pid i。
- **載入**：`require_build_done` → embed 設定比對（列出不同欄位、提示 `build --force`）→ 向量庫檔案存在
  → `load_local(..., from_config("query"), allow_dangerous_deserialization=True, distance_strategy=MAX_INNER_PRODUCT)` → `IndexFlatIP` 且 `d == dim`。
- 檢查一律用明確 `raise`，不用 `assert` 敘述（同 A2）。

## 3. Checkpoint 格式與續跑規則（`embed_ckpt_dir/`）

- `ckpt_meta.json`：`{embed_model, query_prefix, doc_prefix, dim, passage_words, passage_stride, limit, n_passages}`（Q3）。
- 每批一檔 `{start:07d}-{end:07d}.npy`：float32 `(end-start, dim)`、已 normalize，pid 範圍 `[start, end)`；`np.save` 到 `.tmp` 後 `os.replace`。
- **開始時**：(1) meta 不存在或不同 → 清空目錄、寫新 meta（stderr 列出不同欄位）；(2) 刪除 `*.tmp`；
  (3) 從 pid 0 起要求首尾相接、形狀與 dtype 正確、可讀取；第一個不合格檔案及其後全部刪除；(4) 從涵蓋到的 `end` 續跑。
- `batch_size` 不入 meta：續跑只看 pid 範圍。規模：全量約 379 MB、約 1,926 檔；組裝時每次只讀一檔。

## 4. V0 查證結果（2026-11-27；8 GB 級 GPU；腳本與輸出在 `scratch/a3/v0_*`）

**VERIFY-15：`num_gpu` 有效**
- 原始碼：`OllamaEmbeddings.num_gpu` 經 `_default_params` 放進 `options` 送到 `/api/embed`（攔截 request body 確認 `"num_gpu": 0`；值為 None 的鍵也會送出，Ollama 忽略）。
- `/api/ps`：查詢模式 embeddinggemma `size_vram = 0`（0% GPU）；`ChatOllama(qwen3:8b, num_ctx=8192)` 100% GPU；兩者同時常駐。
- 先 build 模式（100% GPU）再查詢模式 → 重新載入到 CPU（約 1.7 秒），反之亦然。
- **注意**：qwen3:8b **第一次載入**時，Ollama 會卸載已在 CPU 上的 embeddinggemma；下一次 embed 重新載入（約 1 秒），之後兩者共存不再卸載。每個 process 只多付一次。
- 耗時（單句 query）：CPU 暖機中位數約 20 ms（LLM 常駐時相同）；GPU 約 9 ms；冷啟動 0.8–1.9 秒。

**長 passage：Ollama 預設靜默截斷，保留開頭 2,048 tokens（符合 D2）**
- 預設（未傳 `truncate`）= `truncate=true`：`prompt_eval_count = 2048`，向量與「能完整放入的最長字元前綴」cosine ≥ 0.99999（與尾段 0.79–0.82）。
- `truncate=false` → HTTP 400 `the input length exceeds the context length`；整批（64 段）任何一段超長都會整批失敗。
- `num_ctx=8192` 仍是 2,048（模型上限）；`num_ctx=512` 會降到 512 → 不可設定小於 2,048 的 `num_ctx`。
- 全量：字元數 > 2,000 的 16,446 段逐段量測，**53 段（31 篇）超過 2,048 tokens**（約 0.04%），最短的只有 2,399 字元（多為序列化資料、符號密集文字）；字元數 ≤ 2,000 的段落未量測（每字元超過 1 token 才可能超長）。
- 以字元數預先截斷不可靠（同樣 2,048 tokens 可能是 2,400 或 8,000+ 字元），維持 D2：依賴 Ollama 截斷；詞彙檢索仍涵蓋全文。

## 5. 與 A4 `build.py` 的銜接

```text
emb = PrefixedOllamaEmbeddings.from_config("build", cfg)
meta = ckpt_meta_from_config(cfg, limit=limit, n_passages=DocStore(p["docstore"]).count_passages())
if not is_embed_done(p["embed_ckpt_dir"], meta):
    embed_passages(p["docstore"], p["embed_ckpt_dir"], emb, batch_size=cfg["embed"]["batch_size"], ckpt_meta=meta)
if not p["vectorstore_dir"].exists():
    build_vectorstore(p["docstore"], p["embed_ckpt_dir"], p["vectorstore_dir"], emb)
```
- `--force` 由 build.py 清空整個目標資料夾；本模組只管 ckpt 的設定比對與 `.tmp`。build_meta 由 build.py 寫入，`load_vectorstore` 只讀取比對。
- vectorstore 完成後 checkpoint 保留（可重新組裝；是否刪除由 A4 決定）。

## 6. 單元測試（`embed.test.py`，15 項，全部用假 inner；`passages.test.py` 12 項仍通過）

1. 前綴：doc / query 各加恰好一次、順序不變、`|` 兩側與結尾空白保留；整批只呼叫 inner 一次；空 list 不呼叫
2. 已以該前綴開頭 → `ValueError`，且在呼叫 inner 之前檢查；開頭是**另一種**前綴或前綴出現在中間 → 視為一般文字；非 str → `TypeError`
3. normalize：L2 norm ≈ 1、方向不變、回傳 Python float；零向量 → `ValueError`；`l2_normalize` 形狀與 dtype；inner 回傳筆數不符 → `ValueError`
4. 模式：`build` → `num_gpu is None`、`query` → `0`；不合法 mode → `ValueError`；預設 inner 的 model / num_gpu / dimensions（只建物件，不送請求）

## 9. 決定與理由

- **D1** 查詢模式的 `num_gpu=0` 由 `from_config("query")` 固定給出（模式的語意，不是可調參數）。**D2** 長 passage 依賴 Ollama 截斷（第 4 節實測確認）。
- **D3** embedding 階段放在 `vectorstore.py`：checkpoint 的寫入與讀取共用同一份格式定義；`embed.py` 維持單一職責且測試不需 faiss。
- **D4** `load_vectorstore(fixtures)` 是 `open_vectorstore(dir, meta)` 的薄包裝，驗證不需寫入 `fixtures/`。
- **使用者決定（2026-11-27）**：D1–D4 同意；Q1 `num_gpu` 不放進 config；Q2 一律加一次前綴，已以該前綴開頭就 raise `ValueError`；
  Q3 ckpt_meta 記錄 `passage_words`、`passage_stride`、`limit`；Q4 embedding 階段放 `vectorstore.py`；Q5 備案偏好 (a) > (b)（未用到）；V4 題目不進 testset。
- **與計畫的落差**：(1) 新增 `is_embed_done`，讓 build.py 不必知道 checkpoint 格式；(2) `ckpt_meta_from_config` 多了 `limit` 參數（Q3）；
  (3) `build_vectorstore` 從 `ckpt_meta.json` 取 dim，不另傳參數；(4) 增加「截斷 / 損壞檔」的續跑驗證。
