## 2. `rag/lexical.py`

| 名稱 | 說明 |
|---|---|
| `LexicalRetriever(BaseRetriever)` | 欄位 `k: int`（預設 config `k_each`）；資源（Ranker、DocStore）為私有屬性 |
| `LexicalRetriever.from_config(cfg=None)` | `p = paths(cfg["runtime"]["use_fixtures"])` → `require_build_done(p["build_meta"])`（未完成即 raise，不載入索引）→ `load_ranker(p["index_dir"])`、`DocStore(p["docstore"])` |
| `best_passage(query_terms: set[str], passages: list[Passage]) -> tuple[Passage, tuple[int, int]]` | 模組層級純函式，回傳最佳 passage 與 `(不同 term 數, 總命中次數)`（給 V1 檢查） |
| `passage_hits(query_terms, passage_text) -> tuple[int, int]` | 單段的 `(不同 term 數, 總命中次數)` |

`_get_relevant_documents(query)` 流程：
1. `terms = hw_bridge.preprocess(query)`；不經過 HW2 query parser（引號、`AND`、括號都只是普通文字）。`terms` 為空 → `[]`。
2. `Ranker.search(terms, k)` → `[(docid, score)]`（排序規則沿用 Ranker：`(-round(score,6), docid)`）；全部 df = 0 → `[]`。
3. 每篇 `get_passages_by_doc(docid)`，以 `best_passage` 選一段（規則見下）；沒有 passage 的文件（理論上不會命中）略過並寫 stderr。
4. 組成 `Document(page_content=passage.text, metadata=1.4 的 7 欄)`：`trec_id`、`url` 取自 `get_doc`；`score` = Ranker 分數（`float`）；`rank` = 1 起算；`sources = ["lexical"]`。

**最佳 passage 規則**（2.6 第 3 步）：對每段 `preprocess(passage.text)`，只計算屬於 query term 集合的 token。
- 排序鍵（Q2 決定，已改 2.6）：`(命中的不同 query term 數, 總命中次數, -pid)` 取最大，即先比涵蓋度、再比總次數、同分取 pid 較小者；避免「flute flute flute」勝過「premiere of the Magic Flute」。
- 所有段落命中數都是 0（切段邊界讓 tokenize 結果與索引不同時才可能）→ 取 pid 最小的一段，不丟掉這篇文件；V1 統計這種情況的次數。
- 不使用索引的位置資訊（2.6：位置對不回清理後文字）。

## 3. `rag/fusion.py`

| 名稱 | 說明 |
|---|---|
| `rrf_fuse(lexical, semantic, *, rrf_k: int, semantic_min_score: float \| None = None) -> list[Document]` | 純函式；`rrf_k` 必須是 ≥ 0 的整數，否則 `ValueError`；`None` = 不過濾 |
| `HybridRetriever(BaseRetriever)` | 欄位 `lexical`、`semantic`（`BaseRetriever`）、`rrf_k`、`semantic_min_score`；`_get_relevant_documents` = 兩路各 `invoke(query)` 後呼叫 `rrf_fuse` |
| `HybridRetriever.from_config(lexical, semantic, cfg=None)` | `rrf_k`、`semantic_min_score` 取自 config `[retrieval]` |

- 不匯入 lexical / semantic / hwlib / faiss（只用 `langchain_core` 與 `rag.config`）；組裝放在 `retrieve.py`。
- **輸入**：兩路都是已依 rank 排序、docid 不重複的清單（語意那一路已去重）。`rank_i(d)` = 該清單中的位置 + 1（不信任上游的 `metadata["rank"]`）；同一清單 docid 重複 → `ValueError`。
- **分數**：`score(d) = Σ 1 / (rrf_k + rank_i(d))`（不加權，Q1 不採用 (b)）。排序以 `fractions.Fraction` 精確計算（避免浮點誤差把該同分的拆開、或反之），`metadata["score"]` 存 `float`。
- **語意門檻**（Q1 (d)）：只出現在語意那一路、且語意 `metadata["score"]` < `semantic_min_score` 的文件不納入（等於門檻保留）；兩路都有的文件不受影響。過濾不改變語意那一路其他文件的名次。
- **排序**（Q1 (a)）：score 遞減 → 兩路都有 > 只有詞彙 > 只有語意 → docid 遞增。同一路的名次不會相同，所以 docid 規則實際上只作用在「兩路都有」的同分文件。
- **passage**：兩路都有 → 用語意那一路的 `pid` 與 `page_content`；否則用該路的。`trec_id`、`url` 取同一份 Document。
- **sources**：固定順序 `["lexical", "semantic"]` 的子集；`rank` 重新編號 1..n；回傳全部合併結果（截斷交給 `retrieve`）。

## 4. `rag/retrieve.py`

- `retrieve(query, k=None, mode="hybrid") -> list[Document]`（1.4 簽名不變）。
  - `k is None` → config `k_final`；`k < 1` → `ValueError`；`mode` 不在三者之中 → `ValueError`。
  - 回傳前 `k` 筆、`rank` 重新編號；每個 docid 至多一筆。可用筆數不足 `k` 時直接回傳較少的筆數（單一路最多 `k_each` 篇）。
- retriever 在第一次使用時建立並快取（整個 process 一份）：lexical、semantic 各一個，hybrid 共用這兩個實例，不重複載入索引與向量庫。
- 語意那一路的來源見第 7 節；semantic 接上前 `mode` 為 semantic / hybrid 時 raise。三種 mode 的 metadata 欄位與型別一致（V4 檢查）。

## 9. 使用者決定（2026-11-28）

- **Q1 同分規則：(a) + (d)，τ = 0.30**（`[retrieval] semantic_min_score`）。理由：
  - 採用 (a)：不改變分數、沒有參數；就算門檻沒擋下雜訊，同分時詞彙那一路的文件仍排在語意雜訊之前。
  - 採用 (d)：學號題 References 中的語意雜訊降到 0；fact 題不受影響。
  - τ = 0.30：高於學號題語意雜訊的最高分（0.279），遠低於 paraphrase gold（0.492）。
  - 兩種出錯方式的代價不對稱：門檻太低只會退回 (a) 的結果；門檻太高才會擋掉只在語意那一路出現的 gold，造成實際損失。目前的門檻離 gold 很遠、離雜訊很近，偏向安全的一側。
  - 不採用 (b)：在 4 題中看起來最好，但 paraphrase 題若只被語意那一路命中，gold 會掉到第 17 名之後，這個風險沒有被測到。
  - 不採用 (c)：每題的雜訊都增加。
  - 限制：門檻只用 4 題、一組 embedding 設定定出；B 的 eval 要檢查只被語意那一路找到的 gold 分數，低於門檻就調低（3.5）。
- **Q2**：同意，最佳 passage 先比不同 query term 數、再比總命中次數、同分取 pid 較小者；已改 HW3.md 2.6。
- **Q3**：semantic、hybrid 在 semantic 接上前直接 raise；不用空清單假實作；fusion 驗證用 scratch 的暫時語意查詢。
- **Q4**：`from_config(cfg=None)` + 欄位 `k` 的設計只記在本檔，暫不寫進 HW3.md 2.6、3.3。
- **Q5**：同意 `Fraction` 精確比較、名次取清單位置、可用筆數不足時回傳較少筆數、retriever 以 process 為單位快取。
