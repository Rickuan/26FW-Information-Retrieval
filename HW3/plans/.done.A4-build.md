## 2. `main.py` 與子指令註冊

- 執行：在 `HW3/` 下 `uv run python src/main.py <子指令> [選項]`；`sys.path[0]` 為 `src/`，直接 `import rag.xxx`，不操作 `sys.path`。
- `main.py` 只有一張表 `COMMANDS = {"build": "rag.build", "query": "rag.cli", "eval": "rag.evaluate"}`（B 的兩項預先列好）與分派邏輯；不讀 config、不做 I/O。
- **子指令模組協定**（每個子指令在自己的模組中實作，這就是註冊方式）：
  - `HELP: str`：一行說明（`main.py -h` 列出）
  - `add_arguments(parser: argparse.ArgumentParser) -> None`：加入自己的選項
  - `run(args: argparse.Namespace) -> int`：回傳 exit code
- 分派：讀第一個參數 → `importlib.import_module` **只匯入被選中的模組**（build 不必載入 LLM、query 不必載入 hwlib 建置路徑）→ 建立 `prog="main.py <子指令>"` 的 parser → `add_arguments` → 解析其餘參數 → `sys.exit(run(args))`。
- 模組尚不存在（B 未完成）時，只有呼叫該子指令會報「尚未實作」並 exit 2；其他子指令不受影響。`-h` 不匯入任何子指令模組。
- **B 加入 query / eval**：在 `rag/cli.py`、`rag/evaluate.py` 實作上述三項即可，不修改 `main.py` 與 `build.py`。

## 3. `build.py` 介面

| 名稱 | 說明 |
|---|---|
| `HELP`、`add_arguments(parser)`、`run(args) -> int` | 子指令協定；選項 `--limit N`（必填數字，Q3）、`--force` |
| `build(limit: int \| None, force: bool, cfg=None) -> dict` | 實際流程；回傳各階段 `{action: "run"/"skip", seconds}`（供驗證腳本直接呼叫） |
| `BuildMismatchError(RuntimeError)` | 既有 build_meta 與目前 config / `--limit` 不一致 |
| `UnmanagedArtifactsError(RuntimeError)` | 目標中有產物但沒有 build_meta（第 7 節） |

- exit code：0 完成；2 前置條件不符（`injected_warc` 不存在並提示 `uv run python tools/inject_warc.py`、`limit < 1`、上述兩種錯誤）；1 階段執行失敗（traceback 到 stderr）；130 Ctrl-C（build_meta 保持 `in_progress`）。
- 進度與耗時只寫 stderr：開頭印目標（正式 / fixtures、limit、相對路徑），每階段印 `run` 或 `skip（原因）` 與秒數，`embed_passages` 自帶每 10 秒進度，最後印各階段耗時表與總耗時。stdout 不輸出。

## 4. 流程

1. `cfg = get_config()`；`p = paths(limit is not None)`（不讀 `use_fixtures`）；目標 = `index_dir`、`docstore`、`vectorstore_dir`、`embed_ckpt_dir`、`build_meta`（含 `docstore.tmp`、`vectorstore_dir.tmp`）。
2. 檢查 `limit`、`injected_warc` 存在。
3. `--force`：刪除上述目標（第 6 節）；否則比對 build_meta（第 5 節），或在 build_meta 不存在時套用第 7 節規則。
4. 寫入 build_meta（`status: "in_progress"`；`.tmp` → `os.replace`，上層資料夾自動建立）。`status` 原本為 `in_progress` 時提示「上次建置未完成，從中斷處繼續」。
5. 依序執行各階段（跳過條件見下表）；index 階段之後**每次**執行 `check_docid_contiguous`（不論是否跳過）。
6. build_meta 改為 `status: "done"`（原子寫入）。

| 階段 | 跳過條件 | 不跳過時 |
|---|---|---|
| index | `index_dir/metadata.json` 存在且可解析（hwlib 最後寫它） | 刪除整個 `index_dir`，`build_lexical_index(injected_warc, index_dir, limit)` |
| norms | index 未重建，且 `load_ranker(index_dir)` 成功（含 preprocessor、norms 對三個來源檔的 sha256 與 N 檢查） | `build_doc_norms(index_dir)`，再 `load_ranker` 確認一次 |
| docstore | index 未重建，且 `docstore` 檔案存在（原子寫入，A2） | 刪除舊檔，依 A2 第 4 節呼叫 `build_docstore` |
| embed | `is_embed_done(embed_ckpt_dir, ckpt_meta)`（`n_passages` 取自 `DocStore.count_passages()`） | `embed_passages`（自動續跑；設定不同時由 A3 清空 ckpt 重來） |
| vectorstore | docstore 未重建、embed 沒有新批次，且 `vectorstore_dir` 存在（原子寫入，A3） | `build_vectorstore`（取代既有目錄） |

- **連帶重建**：index 重建 ⇒ norms、docstore 重建（docstore 寫入後會再與新 doc_map 比對）；docstore 重建或 embed 有新批次 ⇒ vectorstore 重組（全量估計 1–2 分鐘）。
- embed checkpoint 不隨 docstore 重建而刪除：ckpt_meta 含切分參數、`limit`、`n_passages`，docstore 由同一份 WARC 決定性產生（A3 V2 已驗證向量逐位元相同）。
- index 不採用 `.tmp` 資料夾：`build_lexical_index` 直接寫入 `index_dir`，`index.tmp/` 也不在 `.gitignore` 的規則內；改以「metadata.json 最後寫入 + norms 的 sha256 檢查」判定完整（Q5）。
- vectorstore 完成後保留 embed checkpoint（全量約 379 MB）：刪除後重跑時 `is_embed_done` 會失敗而重新 embed 約 41 分鐘（Q4）。

## 6. `--force` 與 `--limit`

- `--limit N`：目標為 `paths(True)`，只處理前 N 篇（索引、docstore、passage、embedding 同時套用）；不讀也不寫正式產物。沒有 `--limit` 時目標為 `paths(False)`。
- `--force`：只刪除第 4 節列出的目標路徑（`--limit` 時即 `fixtures/` 下的同名路徑），然後重建全部階段；不刪除 `fixtures_dir` 或 `store/` 整個資料夾，不動 `dataset/`、`eval/`、`output/`。
- 刪除前的防呆（不通過就 raise、不刪任何東西）：每個路徑解析後位於 `HW3_ROOT` 之內且不等於它；`--limit` 時必須位於 `fixtures_dir` 之內，正式建置時必須不在其內（`config.py` 已保證，這裡再確認一次）。

## 7. 既有索引（`HW3/index/`，手動以 04_injected.warc 建立，無 build_meta）的處理

- **一般規則**：build_meta 不存在，但任一目標已存在 → `UnmanagedArtifactsError`，列出既有產物，提示 `--force`，exit 2。避免沿用來源不明的產物。
- (a) **要求 `--force` 全部重建（採用）**：多花約 9 分鐘（索引約 8.5–9 分鐘、norms 約 15 秒）。無來源風險；全量建置同時是 index 階段的第一次全量實測。
- (b) **新增一次性選項 `--adopt-index`**：只在 build_meta 不存在、目標中只有 `index_dir` 時允許；先執行連續性檢查、`load_ranker`、N 與 doc_map 筆數，並以 `preprocess(學號)` 查詢每個學號，命中的 trec_id 必須恰好等於 config 的 `target_trec_ids`，全部通過才寫 build_meta 並跳過 index、norms。
  - 風險：無法確認建立時的 hwlib 與 charset-normalizer 版本（VERIFY-14：版本不同時 29 篇的文字不同）；這類差異不影響學號查詢與 docid 比對，會讓索引與 docstore 的文字靜默不一致。另需維護一條只用一次的程式路徑。
  - 省下約 9 分鐘（全量約 45 分鐘，而非 50–55 分鐘）。
- 不採用：沒有選項時自動沿用（會靜默接受任何殘留產物）；在 scratch 手寫 build_meta（build_meta 應只由 build.py 寫入）。
